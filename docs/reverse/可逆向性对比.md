# 0.2.6 vs 0.3.1-alpha3：可逆向性实测

> 目的：回答"新版是不是加密更厉害、还能不能反编译出完整代码来改深层功能"。
> 方法：dex 结构解析 + jadx 1.5.6 全量反编译 + 产物逐类核对。**仅静态分析，未做动态验证。**
>
> 结论先行：**0.3.1-alpha3 没有任何加密或加固，反编译完整度比 0.2.6 更高。**
> 改功能变难的真正原因是 R8 的类合并，不是加密。

---

## 0. 版本关系（先确认基线）

`dist/Xemby-tv-1.2-samepkg.apk` 的 5 个 dex 与 `0.3.1-alpha3` **CRC 逐字节相同**：

| dex | 0.3.1-alpha3 | 1.2 母包 |
|---|---|---|
| classes.dex | `fcd72332` | `fcd72332` |
| classes2.dex | `945febf3` | `945febf3` |
| classes3.dex | `878d8670` | `878d8670` |
| classes4.dex | `42d3523f` | `42d3523f` |
| classes5.dex | `247049e5` | `247049e5` |

1.2 只多了 `classes6.dex`（sync 注入，11 个类）和签名。**本文所有结论对 1.2 完全适用。**

## 3. 那为什么改起来难？三个真实原因

### 3.1 详情页：代码量 6 倍，还被合并进一个类

这是最核心的差异。按 `DetailScreen.kt` 留下的 trace 统计：

| | 0.2.6 | 0.3.1-alpha3 |
|---|---|---|
| 相关 java 文件 | 44 个 | 27 个 |
| **合计体积** | **0.8 MB** | **4.9 MB** |
| 最大单文件 | 535 KB（`y/f2.java`，29 处 trace） | **4.4 MB（`ra0.java`，112 处 trace）** |
| 最大单类方法数 | — | **950** |
| 最大单类行数 | — | **60,847 行** |

两件事同时发生：

1. **功能确实变多了**：0.3.1 的详情页新增了 Trakt 同步、外部播放器选择、
   剧集版本、演员卡片、合集、其他服务器资源等，代码量是 0.2.6 的 6 倍。
2. **R8 把它合并了**：`DetailScreen.kt` 里 49 个 Composable 中的绝大部分
   被塞进 `defpackage/ra0.java` 一个类。

结果就是：打开 `ra0.java` 要在 6 万行里找 `A()`、`B()`、`k1()`。类边界没了。

### 3.2 包结构被拍平

| | 0.2.6 | 0.3.1-alpha3 |
|---|---|---|
| 混淆类放在哪 | 46 个单/双字母短包（`t/`、`d0/`、`l0/`…） | **全部拍平到 `defpackage`** |
| 文件数 | 503 | **2,708** |
| 类数 | 1,164 | **3,305** |

0.2.6 至少还能按短包分桶；0.3.1 是 2,708 个 `defpackage.xx0` 平铺在一个目录。

### 3.3 业务代码被"污染"的比例差 15 倍

统计 `com.dh.myembyapp.*` 里每条 `import` 指向混淆包的比例：

| | 0.2.6 | 0.3.1-alpha3 |
|---|---|---|
| 总 import | 1,610 | 2,059 |
| 指向混淆包 | 18（**1.1%**） | 331（**16.1%**） |
| 被引用的混淆类 | 15 | 93 |

0.2.6 的业务类几乎只依赖语义类，改功能顺着 `import` 就能读完。
0.3.1 每 6 条 import 就有 1 条是 `defpackage.bc0`、`defpackage.f22`。

`MyEmbyApp.java` 最夸张：86 条 import 里 38 条指向 `defpackage`。

## 4. 具体卡在哪：7 个出不来的方法

`ra0` 里这 7 个方法只有签名，没有方法体：

| 方法 | 参数数 | 返回 | 判断 |
|---|---|---|---|
| `ra0.A` | 3 | Object | 协程状态机 |
| `ra0.L` | 31 | void | 详情页巨型 Composable |
| `ra0.d` | **76** | void | 详情页主 Composable（最大） |
| `ra0.e` | 5 | Object | 滚动/焦点协程 |
| `ra0.f` | 7 | Object | 滚动/焦点协程 |
| `ra0.k1` | 1 | String | 字符串处理 |
| `ra0.x1` | 1 | SubtitleLanguagePriorityType | 字幕语言判定 |

这是 jadx 对 Compose 内联状态机的极限，不是加密。只能退回 smali 看。

**但定位不靠类名。** `ra0` 里保留了 49 个 Composable 的原始名字和行号，
按 `DetailScreen.kt:1704` 这种串搜索即可。完整索引见
[`jadx/ra0_DetailScreen_索引.md`](jadx/ra0_DetailScreen_索引.md)。

## 5. 分层可改性

| 层 | 位置 | 可读性 | 能否直接改 |
|---|---|---|---|
| 数据 / 偏好 | `com.dh.myembyapp.data.*` | 高，语义类名 + `@Metadata` 参数名 | ✅ 可以 |
| 网络 / API | `data.api.*` | 高 | ✅ 可以 |
| 服务端 / 配置下发 | `server.*`（60 个类） | 高 | ✅ 可以 |
| DLNA | `dlna.*` | 高 | ✅ 可以 |
| 播放控制逻辑 | `ra0` 部分方法 + `data.model.*` | 中，函数名保留 | ⚠️ 能改，要在大类里找 |
| 详情页 / 播放页 UI | `defpackage.ra0` | 低，7 个巨型方法无方法体 | ❌ 需看 smali |
| 其他 Compose UI | `defpackage.*`（2,708 文件） | 低，类名无语义 | ⚠️ 靠 trace / 文案定位 |
